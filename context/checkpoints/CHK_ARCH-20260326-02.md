# Checkpoint ARCH-20260326-02

- Fecha: 2026-03-26
- Alcance: Corrección de hidratación del shell global con sesión de NextAuth precargada desde servidor.
- Objetivo: Evitar mismatch entre HTML SSR y cliente en rutas autenticadas, especialmente en el workspace de eventos.

## Causa corregida
- El layout renderizaba Providers sin pasar la sesión del servidor a SessionProvider.
- AppShell depende de useSession para pintar nombre de usuario, rol y navegación.
- Eso permitía que el servidor generara un árbol distinto al del cliente durante la hidratación.

## Cambios aplicados
- RootLayout obtiene la sesión con getServerSession(authOptions).
- Providers ahora acepta la sesión inicial y la inyecta en SessionProvider.

## Validación esperada
- Desaparece el error React 418 por hydration mismatch en vistas autenticadas.
- Sidebar, header y nombre del usuario se renderizan de forma consistente entre SSR y cliente.
