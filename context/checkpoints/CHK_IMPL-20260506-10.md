## Resumen de implementación

Se reestructuró `ExamenMedicoEstudio` para incluir 4 pestañas externas en lugar de las 3 sub-pestañas del examen clínico previas. Las pestañas 1, 2 y 3 son prerrequisito para acceder a la pestaña 4.

### Orden de pestañas implementado
1. **Somatometría** — Peso, Talla, IMC (calculado) y Complexión
2. **Signos Vitales** — TA Sistólica/Diastólica, FC, Temperatura, FR, Perímetros
3. **Agudeza Visual** — Campo visual OD/OI, corregida, y pruebas complementarias
4. **Examen Médico** — Módulo 1, Exploración Física e Impresión/Aptitud (bloqueable)

### Regla de bloqueo
- `canAccessExamen = somaCompleted && vitalsCompleted && agudezaCompleted`
- La pestaña 4 muestra un panel "🔒 Examen Médico bloqueado" con links a las pestañas pendientes
- El botón de la pestaña 4 está `disabled` y muestra tooltip explicativo
- Un banner de aviso visible indica qué tabs faltan cuando hay al menos una incompleta

### Persistencia
- Somatometría y Signos Vitales: ambas guardan en `MedicalExam.somatometryData` vía `updateSomatometria` (merge del form soma + vitals)  
- Agudeza Visual: guarda en `MedicalExam.eyeAcuityData` vía `updateAgudezaVisual`
- Examen Médico: persiste en `physicalExamData` vía `saveExamenMedicoPapeleta` (sin cambios)
- `somaCompleted` / `vitalsCompleted` / `agudezaCompleted` se inicializan desde los datos existentes en DB

### EventTest status
- Al guardar Somatometría o Signos Vitales: actualiza el `EventTest` de Somatometría (`somatometryEventTestId`) vía `updateEventTestStatus`
- Al guardar Agudeza Visual: actualiza el `EventTest` de Agudeza Visual (`agudezaEventTestId`) vía `updateEventTestStatus`
- Ambos IDs vienen por props desde `PapeletaWorkspace`

## Riesgos y pendientes reales

1. **Signos Vitales comparte save con Somatometría**: Ambas pestañas llaman `updateSomatometria` haciendo merge de ambos forms. Si el usuario solo guarda Vitales sin haber tocado Somatometría, se pierde el calc de IMC (peso/talla vacíos). Mitigación: el merge incluye los valores actuales de `somaForm` en `handleSaveVitals`.
2. **`completedCount` en cabecera no se actualiza optimistamente** para soma/agudeza (el `localTests` no se modifica cuando se guardan desde dentro de Examen Médico). Se resuelve en el `router.refresh()` que dispara `onExamenMedicoStatusChange` al completar la pestaña 4.
3. **Sidebar activo**: Si el usuario tiene abierto un soma/agudeza en `activeTestId`, ese ID ya no existe en `visibleTests`. Al volver atrás verá la lista correcta. No hay crash porque el panel del estudio activo usa `activeTest` directo de `localTests`, no de `visibleTests`.
4. **Tests E2E**: Requieren validación manual en entorno con node_modules (`pnpm install && pnpm dev`).
