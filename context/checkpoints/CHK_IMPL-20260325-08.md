## Resumen Ejecutivo

Se implementó el modelo dual de prellenado longitudinal: los datos declarativos del trabajador (capturados vía portal de prellenado) se persisten en `ClinicalHistory.data.prefill_base` como **base longitudinal**, separada del snapshot por cita (`PrefilledInvitation.module1Data`). Esto permite que:

1. El portal inicialice con datos previos de citas anteriores (sin sobrescribir el snapshot por cita)
2. La historia clínica del trabajador muestre ambas fuentes en pantallas distintas
3. El examen médico, dentro de una cita, siga viendo el snapshot de esa cita específica

---

## Decisiones Arquitectónicas

| Decisión | Justificación |
|----------|--------------|
| Sub-clave `prefill_base` en `ClinicalHistory.data` (Json) | Sin migración de schema. `ClinicalHistory.data` ya es `Json` flexible en Prisma. |
| No fusionar con `patologicos`/`heredo_familiares` del médico | Evita contaminación entre datos declarativos del trabajador y datos clínicos del médico. |
| Somatometría/Agudeza Visual fuera del scope | Conforme SPEC — columnas separadas, no tocar. |
| `getPrefilledDataForEvent(eventId)` — nueva función | Permite al evento cargar el snapshot sin acoplamiento directo a PrefilledInvitation desde la página. |

## Flujo de Datos

```
Portal Trabajador (prefill/[token])
    │
    ▼
submitModule1()
    ├── PrefilledInvitation.module1Data  ← SNAPSHOT POR CITA (inmutable tras submit)
    └── ClinicalHistory.data.prefill_base ← BASE LONGITUDINAL (actualiza en cada cita)

validatePublicToken()
    └── Si invitation.module1Data === null
        └── Fallback: ClinicalHistory.data.prefill_base
        └── Retorna: { existingData: prefill_base, fromLongitudinalBase: true }

history/[workerId]/page.tsx
    └── AntecedentesForm — datos clínicos (médico)
    └── Panel "Historia Declarativa Base" — prefill_base (solo lectura)

events/[id]/page.tsx
    └── getPrefilledDataForEvent(id) → snapshot de PrefilledInvitation.module1Data
    └── PapeletaWorkspace ← prefilledData (snapshot de ESA cita)

ExamenMedicoEstudio
    └── Banner + panel colapsible con snapshot de la cita (referencia para el médico)

PrefillPortalClient
    └── Banner informativo si fromLongitudinalBase === true
```

## Bug Resuelto Durante Implementación

**Error:** `Type 'unknown' is not assignable to type 'ReactNode'` en `history/[workerId]/page.tsx:122`

**Causa raíz:** `prefillBase` tipado como `Record<string, unknown>` hacía que las expresiones `&& JSX` en JSX evaluaran a tipo `unknown`, no permitido como child.

**Solución:** Declarar interfaz `PrefillBase` con propiedades específicamente tipadas como `Record<string, string | number | boolean>`, eliminando el `unknown` del árbol de tipos.
