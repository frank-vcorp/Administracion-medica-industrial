## Problema resuelto

Antes: la UI solo exponía un booleano `isUploading` → el usuario veía un estado opaco
"Subiendo archivo..." sin saber si el sistema seguía trabajando, se había trabado, o el
pipeline IA ya estaba corriendo.

Después: el usuario ve una barra de progreso y un stepper de 5 etapas con la etapa
activa resaltada mientras corre el pipeline completo.

### Detalle de cambios en PapeletaWorkspace.tsx

1. **Nuevo tipo**: `UploadStageId` (union literal de 5 etapas)
2. **Nueva constante**: `AI_PIPELINE_STAGES` (array con id, label, pct por hito)
3. **Nuevos estados**: `uploadStage: UploadStageId | null`, `regenStage: UploadStageId | null`
4. **`handleFileUpload` extendido**: avanza etapas con 4 timeouts (3s / 7s / 15s / 28s); los
   cancela al recibir respuesta del backend; muestra 'saving' 700ms antes de limpiar
5. **`handleRegenerateAI` extendido**: igual pero arranca en 'classifying' (archivo ya subido);
   timeouts en 4s / 10s / 22s
6. **`StudyPanel`**: recibe `uploadStage` y `regenStage` como nuevas props (con tipos)
7. **Dropzone reemplazado por `UploadProgressPanel`** cuando `isUploading && uploadStage`
8. **Botón regen reemplazado por `UploadProgressPanel`** cuando `isRegenerating && regenStage`
9. **Nuevo sub-componente `UploadProgressPanel`**: barra + stepper, prop `isRegen` para
   variante de regeneración (filtra etapa 'uploading' del stepper)

## Regla de honestidad UX aplicada

Los porcentajes (10% / 25% / 50% / 80% / 100%) son hitos visuales orientativos, no métricas
de bytes ni de tiempo real del backend. El copy del panel lo declara explícitamente:
> "El progreso mostrado es orientativo, no telemetría exacta del backend."

---

## Riesgos residuales

| Riesgo | Severidad | Mitigación aplicada |
|--------|-----------|---------------------|
| Si el backend responde en <3s, el usuario ve solo "Subiendo archivo" antes del salto final a "Guardando" | Bajo | Aceptable: el flash de 'saving' 700ms es correcto y honesto |
| Si el backend tarda >28s, la UI muestra "Guardando resultado" prematuramente | Bajo | Pipeline normal es 15-35s; el timeout t4=28s es conservador pero puede coincidir |
| Timers no se limpian si el componente se desmonta antes de resolver | Bajo | React no crashea; los setState en componente desmontado generan warning pero no rompen flujo. En producción Next.js esto es infrecuente para esta ruta |
| La variante `isRegen` filtra "Subiendo archivo" del stepper pero el archivo ya subido muestra `pct=25%` desde el inicio | Aceptable | Honesto: el archivo ya estaba subido, empezar en clasificación es correcto |
