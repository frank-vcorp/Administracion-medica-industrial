## Flujo de Datos Implementado

```
generate_prediagnosis(study_type, extracted_data, medical_calibration)
    ↓ build prompt (rendered_prompt capturado aquí)
    ↓ call LLM (featherless / gemini)
    ↓ result = AIPrediagnosisResult(**raw_result)
    ↓ result.input_debug = PrediagnosisInputDebug(
          study_type, extracted_data, medical_calibration,
          clinical_provider, clinical_model_used, rendered_prompt
       )
    ↓ return result

main.py /api/v2/studies/upload-and-analyze
    → prediagnosis_snapshot.input_debug = prediagnosis.input_debug.model_dump()

main.py /api/v2/studies/prediagnosis-from-params
    → response.input_debug = prediagnosis.input_debug.model_dump()

frontend: prediagnosisData (JSON en DB) incluye input_debug automáticamente
    → StudyAIPrediagnosisPanel lee predxData.input_debug
    → <StudyPrediagnosisRawPanel inputDebug={predxData.input_debug} />
       - Si null → retorna null (compat snapshots viejos)
       - Si existe → panel colapsable con extracted_data + calibration + rendered_prompt
```

## Riesgos Residuales

| Riesgo | Severidad | Mitigación |
|--------|-----------|------------|
| `rendered_prompt` puede ser largo (~3-5KB por estudio) y aumentar tamaño del JSON en DB | Bajo | El campo es visible solo bajo toggle explícito; no se renderiza en la vista normal |
| Rutas `AI_NON_CONCLUSIVE` tempranas no tienen `input_debug` | Bajo | El campo es `Optional=None`; el componente retorna `null` si no hay datos. En V2 se puede agregar `input_debug` parcial a esas rutas |
| `medical_calibration` puede ser un dict grande si el panel aiCalibration tiene muchos criterios | Bajo | Solo se persiste el dict clínico; no hay secretos en ese dict |
| El campo `clinical_provider` en `AIPrediagnosisResult` usa `Literal["gemini", "featherless"]` pero el código también asigna `"gemini_fallback"` en el fallback de Featherless gated | Pre-existente | Este issue pre-existe a IMPL-20260516-08; Pydantic lo acepta con coerción o lanza ValidationError.
