## 3. Hallazgos priorizados

### F-1 — P2 Media: Test `test_AC_4_3b` no detecta callers multi-línea (cobertura engañosa)

**Evidencia (líneas reales):**
- `backend/app/main.py:1491-1497` — `v2_prediagnosis_from_params` aún invoca:
  ```python
  prediagnosis = prediagnostic_svc.generate_prediagnosis(
      study_type,
      extracted_data,
      calibration_version=calibration_version,
      ai_calibration=ai_calibration,
      medical_calibration=medical_calibration,  # DEPRECADO Fase 4
  )
  ```
- El test filtra por línea `"prediagnostic_svc.generate_prediagnosis(" in line and "medical_calibration=" in line` — el calificador está en línea contigua (1496), no en la misma línea que abre el call (1491). El test pasa por construcción.
- Verificación independiente multi-línea con regex: **1 de 3 callers** (`v2_prediagnosis_from_params`) sigue pasando `medical_calibration=` como kwarg al servicio. Los otros 2 callers (`v2_upload_and_analyze:1310`, `v2_event_test_upload_xml_audiometry:1753`) ya NO lo pasan.

**Impacto:** comportamiento real **cumple** la SPEC (handoff §6.3 autoriza explícitamente mantener shim deprecado en callers legacy no migrables) y `prediagnostic.py:798-810` loguea warning único por proceso al recibir el kwarg. Sin embargo, la afirmación del IMPL-REPORT §3 AC-4.3 y del test ("0 llamadas activas a `medical_calibration=`") es **literalmente falsa** para `main.py` y la cobertura del AC-4.3 contra regresiones futuras es insuficiente.

**Reproducción:**
```python
import re; from pathlib import Path
main = Path('backend/app/main.py').read_text()
matches = re.findall(r'prediagnostic_svc\.generate_prediagnosis\(\s*\n((?:.*?\n)*?)\s*\)', main)
print([('medical_calibration=' in m) for m in matches])
# → [False, True, False]   (1 caller sigue activo)
```

**Owner:** SOFIA. **Condición de cierre:** ajustar el assert a multi-línea (regex `re.search` sobre cada llamada capturada por `re.finditer`) o complementar con `ast` module; o actualizar el docstring del test declarando explícitamente "excepto el shim `medical_calibration=medical_calibration, # DEPRECADO Fase 4` permitido por handoff §6.3". Recomendación: **AST-based matcher** para que el grep cubra todas las formas válidas.

### F-2 — P3 Baja: `v2_prediagnosis_from_params` puede degradar a `calibration_version=None` bajo loop asyncio activo

**Evidencia (`main.py:1430-1490`):** el endpoint es `def` (sync). Cuando hay un asyncio loop activo en el thread (poco probable en endpoint sync vía threadpool, pero posible en tests/Repl/invocación programática), `asyncio.get_running_loop()` no lanza `RuntimeError` y el código emite warning + retorna `calibration_version=None`. Resultado: cae a `legacy_hardcoded` aunque se haya pasado `medical_test_id`. Los otros 2 callers (`v2_upload_and_analyze`, `v2_event_test_upload_xml_audiometry`) son `async` y resuelven sin este riesgo.

**Impacto:** la degradación está documentada en IMPL-REPORT §6 / §6.7 y autorizada por handoff §6.3. Bajo FastAPI sync threadpool + `asyncio.run`, funciona. Si se observa el warning en logs de producción, el endpoint pierde V3-driven IA pero conserva `ai_calibration` legacy como fallback explícito (si lo pasó el caller) o `legacy_hardcoded` (con `legacy_hardcoded_reason` poblado).

**Owner:** SOFIA fix optativo (puede marcarse como aceptación operativa). **Condición de cierre:** si se decide cubrir: convertir `v2_prediagnosis_from_params` a `async def` para resolver consistentemente, o usar `asyncio.run_coroutine_threadsafe` con un loop de referencia. Riesgo actual: bajo — no reproducible en carga normal; documented.

### F-3 — P3 Baja: Sin test de integración HTTP `POST /upload-and-analyze` con Prisma real (Form `medical_test_id`)

**Evidencia:** los 10 tests nuevos son unitarios sobre `PrediagnosticService.generate_prediagnosis` con `calibration_version` sintética (`_FakeAICalibrationVersionResolved`). El flujo end-to-end `multipart/form-data` con `medical_test_id` → `prisma.medicaltest.find_unique` → `get_default_resolver().resolve(...)` → servicio sólo está cubierto por el wiring manual (`main.py:991-1032`). No hay test E2E/smoke que valide el camino real.

**Impacto:** el camino crítico (resolución DB → resolver → servicio) sólo está validado por inspección estática y por el contrato `TestNoSecretsExposed` del resolver. Si el resolver devuelve un shape inesperado (e.g., `clinicalCriteria` no-dict), el código externo de `_resolve_clinical_criteria` (`.get("prediagnosisEnabled")`) lanzaría `AttributeError` en runtime.

**Owner:** INTEGRA (decisión de cobertura Fase 4 vs diferir a Fase 5/7) / SOFIA (si decide añadir test de integración). **Condición de cierre:** añadir test de integración `tests/test_integration_upload_and_analyze_medical_test_id.py` mínimo (smoke con TestClient + Prisma mock o fixture in-memory), o diferir explícitamente a Fase 7 y documentar la limitación.

### F-4 — P3 Baja: Contrato público extensible — sin validación formal de backward-compat de schema

**Evidencia:** `AIPrediagnosisResult.calibration_source`, `prompt_source` y `legacy_hardcoded_reason` extienden `Literal` types. `PrediagnosisInputDebug` añade `calibration_version: Optional[Dict[str, Any]]`. Consumers externos (clientes Python/TS que consuman Pydantic serializado) que reciban los nuevos campos no romperán (opcionales), pero no hay schema versionado formalmente (`schemaVersion` interno del resolver sí, schema de respuesta HTTP no).

**Impacto:** Bajo. LaSPEC §18.4 ya autoriza compat aditiva. El cambio es backward-compat por construcción (campos opcionales con default). Documentar en `context/SYSTEM.md` o añadir header `X-Response-Schema-Version: ARCH-20260820-01-Fase4` es opcional.

**Owner:** INTEGRA (decisión arquitectónica, no-bloqueante Fase 4). **Condición de cierre:** documentar el contrato additivo en SYSTEM.md o diferir.
