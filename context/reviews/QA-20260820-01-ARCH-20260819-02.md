## D. Hallazgos priorizados

### P2 — F-1: Baseline de tests rojo en `main` (preexistente, no atribuible al incremento)
- Evidencia: `npx vitest run src/actions/__tests__/medical-exam.actions.test.ts` → 15 fallos tanto en la rama como en `main`. Errores Zod de `ImpresiónAptitudSchema.parse` (`estado_nutricional`, `salud_bucal` undefined) en tests de payloads legacy (p.ej. línea 1085).
- Impacto: AC-13 no puede cumplirse literalmente ("todos los tests pasan"). El HANDOFF afirmaba "baseline verde (vitest 273+/273+)": inexacto (la suite real tiene 617 tests con 15 rojos). Posible regresión de validación en `main` asociada al Corte 4.5 (`39858d2`, tip de main): si el schema rechaza payloads legacy en runtime, el guardado de exámenes legacy podría fallar — no demostrado más allá de los tests.
- Reproducción: `cd frontend && npx vitest run src/actions/__tests__/medical-exam.actions.test.ts` en `main`.
- Criterio/contrato: AC-13; DoD "preservar verde".
- Owner recomendado: INTEGRA (evaluar dictamen DEBY sobre `ImpresiónAptitudSchema` / IMPL-20260817-12 en `main`).
- Condición de cierre: suite de actions verde en `main`, o excepción documentada por INTEGRA.
- **No bloquea este incremento** (defecto preexistente; el incremento no añade ningún fallo).

### P3 — F-2: Desviación literal de AC-5 (Audiometría inicia expandida)
- Evidencia: `ResultadosPorPrueba.tsx` inicializa `expanded = { audiometria: true }`; test 5 se titula "inicia expandida por defecto". AC-5 dice "oculto inicialmente; tras click… queda visible".
- Impacto: el contrato §7 regla 8 delega el comportamiento exacto en SOFIA y la capacidad expandir/contraer está demostrada (ambos estados renderizados); pero el literal de AC-5 no se cumple y la interacción de click no está cubierta (los tests usan `renderToStaticMarkup`, sin DOM interactivo — patrón existente del repo, coherente con `vitest.config.ts` `environment: 'node'`).
- Owner recomendado: aceptación por INTEGRA/Frank (es la decisión de UX que el prototipo busca validar).
- Condición de cierre: aceptación explícita, o colapsar Audiometría por defecto (cambio de 1 línea).

### P3 — F-3: Fallback `??` no replica la semántica de `pickText` (borde vacío-string)
- Evidencia: `ResultadosPorPrueba.tsx` usa `form.examen_medico_texto ?? form.impresion_diagnostica ?? ''`; `exam-summary.ts:pickText` trata string vacío como ausente (`nuevo.trim() !== ''`). El HANDOFF indicó "mismo patrón que pickText", pero `??` no cae al legacy cuando el slot nuevo es `''`.
- Impacto: caso borde (slot nuevo vacío + legacy con texto, p.ej. textarea limpiada): la tarjeta mostraría "Pendiente de captura…" mientras el consolidado debajo muestra el texto legacy. Inconsistencia visual, sin impacto en persistencia.
- Owner recomendado: SOFIA vía INTEGRA (fix L1: alinear con semántica `pickText`).
- Condición de cierre: test con `examen_medico_texto: ''` + `impresion_diagnostica: 'X'` mostrando 'X' en la tarjeta.
